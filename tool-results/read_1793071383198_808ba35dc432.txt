   314→## 3. Architecture and ownership
   315→
   316→```text
   317→Portable HTML: chrome + editor + embedded resources + notebookData
   318→                           |
   319→                     startup decode/load
   320→                           |
   321→       files[] + activeId/doc + extra + preferences + revision
   322→             /                         \
   323→   active rich DOM/source             library/maps/sidebar
   324→             |
   325→    commit authored state + scoped Undo + versions
   326→             |
   327→      app-owned browser persistence
   328→             |
   329→   validated revision -> file protection -> packing/compression
   330→             |
   331→    connected HTML stream OR portable HTML download
   332→```
   333→
   334→### Outer documents, inner tabs and maps
   335→
   336→- The notebook has one outer `files` array. `activeId` and `doc` identify the selected outer file. Switching must commit outgoing edits before changing ownership.
   337→- **The active inner tab's authored content lives in the outer file's `markdown`, `richHtml` and `writer`. Inactive tab items hold `item.content`. The active item must not also hold a stale content copy.** Tab switching swaps these payloads and preserves shared library/Google metadata. Undo scope uses the file/tab identity pair.
   338→- `writer.library` holds file membership/tags/star information. Notebook library/folder/collection metadata is stored under `extra["notepad:library:v2"]`.
   339→- Collections are contexts/filters over the same notebook, not independent databases. Folders and links need ID remapping during import/copy/restore.
   340→- A file map projects the library's files/folders; a mind map owns an authored graph in `file.writer.map`. Collapsed nodes are hidden projections, not deleted saved content. Transient cameras/selection must not replace authored positions/edges.
   341→
   342→### Editing representations
   343→
   344→- Rich view uses `#editor` and authored HTML plus writer metadata. `MD.render`/`MD.serialize` bridge Markdown and rich content; not all rich presentation has a Markdown representation.
   345→- Rendered syntax spans, toolbar DOM, page spacers and overlays are presentation. They must not pollute authored history or be confused with saved content.
   346→- Selection can be a native DOM range, directional anchor/focus offsets, source textarea offsets, table-cell selection, image selection or graph selection. These are distinct contracts.
   347→- Comments use thread metadata plus one or more `.np3-cmt[data-cid]` anchors. Fragmented formatting does not imply separate comment threads. B251 shows a current duplicate-card failure after partial clearing/reload.
   348→- Tracked edits are block/paragraph based. Do not describe this as complete Word character-level Track Changes.
   349→
   350→### Persistence and protection
   351→
   352→- `workspaceSnapshot` captures notebook identity/revisions, files, extras and preferences. `_saved*` fields are comparison caches, not separate authored documents.
   353→- Browser persistence, connected-file completion and generated-download creation are separate milestones. A Blob or attempted anchor click does not prove a native download finished.
   354→- `NotepadPacked` deduplicates strings/assets and can compress in a worker. `NotepadFileVault` handles selected-file protection and private extras/history; `NotepadVault` handles notebook/storage protection and serialized writes. Packing is not encryption.
   355→- Source uses WebCrypto PBKDF2-SHA256 and AES-GCM. Existing optional whole-notebook protection and selected-file protection are different policies. Protect names/membership only according to the intended disclosure contract: selected protected-file stubs can retain public names/library context while hiding contents.
   356→- A completed older save must not mark later edits saved or clear their browser copies. Connected writes compare disk/revision state, serialize a snapshot, write/close and check for newer activity.
   357→- Document versions, notebook-level transaction/history records, Undo and app-owned recovery safeguards are separate mechanisms. Current user-facing design requests version history rather than recovery-copy terminology; keep internal safeguards intact during this audit.

   547→## Highest-yield workflow found in this audit
   548→
   549→1. **Read the handoff and requirements before testing.** Identify the exact release, owner(file/tab/collection), mode and intended contract. Search current/historical report and ledger first.
   550→2. **Inspect a final handler and its wrappers.** Look especially for state captured before an await, normalized Range bounds that lose direction, strings normalized differently in history versus rendering, duplicate metadata IDs, and UI status not tied to acknowledged revisions.
   551→3. **Choose one concrete ordinary sequence and a discriminating control.** Examples: pending versus settled highlighting; image versus text clipboard; first versus later table cell; parent versus leaf list item; delayed old versus fresh response; typing before versus during Lock.
